# 全局 Persona 作为配置项，并以事件账本持久化

M7 要求 Agent 有可编辑的全局人设（Persona）。决定：人设采用**结构化字段 + 自由补充**（名字/语气/职责/禁止行为 + 其他），按固定顺序拼装成 system prompt，**同时注入会话与记忆抽取器**，不注入任务规划器（后者需要严格 JSON 输出）；人设以事件 `persona.updated` 持久化并随同步传播，内存缓存读取。

## Considered Options

- **只存配置文件**（如 providers.json 那种）：简单，但不进账本、不同步、无历史，改错了无法回看。
- **只在会话层注入**：会让"人设说你是助手甲"与"记忆里写 Owner 偏好…"割裂——抽取器有自己隐含的助手设定（实测它把"我偏好…"改写成"Owner 偏好…"）。
- **结构化 vs 纯文本**：纯文本自由但容易写出互相矛盾的设定（"回答要简短"+"详细解释每一步"），且无法校验。

## Consequences

- 修改人设会让**所有既有会话的 KV 缓存前缀失效**：下一轮首次请求按全量 prompt 计费，同时历史对话的风格基准改变。UI 保存前必须二次确认并列出受影响会话数（不估算 token 数字——不同供应商的缓存实现不同，估出来是假精确）。
- 抽取器读人设意味着 Persona 也进入后台管线的提示词；改人设会影响后续记忆的措辞（`Owner 偏好…` 里的称谓），历史记忆不重写。
- 拼装顺序固定（名字 → 语气 → 职责 → 禁止 → 其他），以保证前缀稳定性；字段顺序一旦确定不可随意调整，否则缓存全失效。
