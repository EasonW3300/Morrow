# 全局 Persona 作为配置项，并以事件账本持久化

M7 要求 Agent 有可编辑的全局人设（Persona）。决定：人设采用**结构化字段 + 自由补充**（名字/语气/职责/禁止行为 + 其他），按固定顺序拼装成 system prompt，**同时注入会话与记忆抽取器**，不注入任务规划器（后者需要严格 JSON 输出）；人设以事件 `persona.updated` 持久化并随同步传播，内存缓存读取。

## Considered Options

- **只存配置文件**（如 providers.json 那种）：简单，但不进账本、不同步、无历史，改错了无法回看。
- **只在会话层注入**：会让"人设说你是助手甲"与"记忆里写 Owner 偏好…"割裂——抽取器有自己隐含的助手设定（实测它把"我偏好…"改写成"Owner 偏好…"）。
- **结构化 vs 纯文本**：纯文本自由但容易写出互相矛盾的设定（"回答要简短"+"详细解释每一步"），且无法校验。

## Consequences

- **修改人设只影响之后新建的会话**（实现口径，M7-A code-review 后修订）：会话的 system
  prompt 在 **AgentRuntime 创建时**求值一次（`SessionManager` 的工厂调用点），之后该会话
  复用同一运行时，改人设不重建它——既有会话的风格基准与 KV 缓存前缀都保持不变。
  实际影响面是"之后新建的会话（以及尚未创建运行时的会话首次发消息时）"，不是"所有既有会话"。
- 抽取器读人设意味着 Persona 也进入后台管线的提示词；改人设会影响后续记忆的措辞
  （`Owner 偏好…` 里的称谓），历史记忆不重写。
- 拼装顺序固定（名字 → 语气 → 职责 → 禁止 → 其他），以保证前缀稳定性；字段顺序一旦确定
  不可随意调整，否则**新建会话**的缓存前缀全部不同。
- UI 保存前的二次确认仍然保留（FR-A4）：它说明的是"生效范围 = 新会话"与"记忆措辞影响"，
  而不再声称"所有既有会话缓存失效"。

### 为什么当初写成"所有既有会话的 KV 缓存全失效"

起草 ADR 时的假设是"每轮都重新拼装 system prompt 并随请求发送"，那样人设一变，所有会话
的 prompt 前缀都会变，供应商侧 KV 缓存自然全失效——这也是当初要求"保存前二次确认并列出
受影响会话数"的理由。

M7-A-T1 落地时选了更省的实现：**system prompt 随会话运行时创建注入一次**（同一取舍也
解释了为什么附件内容附在 user 消息而不是 system prompt——见 ADR-0012）。两者的差别不是
实现 bug，而是"每轮重拼"与"运行时创建时求值一次"的选择。此处保留原判断的来龙去脉，避免
以后有人把它当成缺陷去"修复"成每轮重拼。
