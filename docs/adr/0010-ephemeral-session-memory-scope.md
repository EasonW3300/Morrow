# 临时会话：只读全局记忆、写入隔离在会话作用域

M7 引入临时会话（Ephemeral Session）：用于一次性问答，不污染长期记忆。决定：临时会话**可以读全局记忆**（否则问"我的偏好是什么"都答不出），但**写入的候选与事实带 `scope=session`**，默认不进入长期记忆池；提供「提升为长期记忆」按钮把单条移出隔离。关闭后保留 24 小时再清理。

## Considered Options

- **完全隔离（读写都不碰全局记忆）**：语义干净，但失去"问我自己偏好"的能力，等于一个无记忆的模型。
- **完全共享（等同普通会话）**：临时会话就没有存在意义。
- **写入直接进全局**：会在随手一问时污染长期画像，违背"临时"的直觉。

## Consequences

- `memory_candidates` 与 `memory_facts` 需要新增 `scope` 维度（`owner` 默认 / `session:<id>`），检索默认只看 `owner` + 当前会话的 `session` 作用域；这是 schema 演进而非新表。
- 清理是**逻辑清理**（标记过期），账本事件保留，遵守 append-only；投影文件与 FTS 索引移除。
- 临时会话里**禁用写入类能力**：不允许注册新能力、不允许生成代码、不允许执行写操作（UI 层禁用 + 服务端拒绝双保险），避免"临时会话偷偷开局"。
- 若 Owner 忘记提升就关闭会话，24 小时内仍可恢复；超过则只留账本证据，不再出现在检索里。
