# 首批渠道：飞书 + QQ 官方 Bot 为稳定基线，微信个人号为实验，Telegram 延后

决策稿 V0.6 原以 Telegram 官方 Bot 为稳定基线渠道。访谈确认 Owner 的日常沟通发生在国内平台，决定翻转首批渠道结构：**稳定基线渠道 = 飞书自建应用 Bot 与 QQ 官方 Bot**。飞书开放平台文档规范完整且支持长连接事件订阅（无需公网回调地址），与 ADR-0004 的私有网络策略直接契合，作为渠道层第一个打穿的对象；QQ 官方 Bot 走官方 API（主动消息受平台限制，须如实声明）。微信个人号维持实验性适配器（声明环境：Windows + 当前最新版微信客户端，出厂默认关闭、每次启动显式确认、风险自担）；QQ 个人号自动化列为实验研究项，不设验收承诺。Telegram 降为后续迭代，仅保留 ChannelAdapter 接口预留。

## Considered Options

- 维持 Telegram 基线（决策稿 V0.6 立场）：技术上最稳，但不符合 Owner 实际使用场景，验收通过也没有真实使用价值。

## Consequences

- AC-09/AC-10 重新分配：AC-09 = 飞书稳定闭环，AC-10 = QQ 官方 Bot 闭环（含主动消息限制声明），新增 AC-15 = 微信个人号实验。
- M4 前置事项：注册飞书开放平台自建应用、注册 QQ 机器人开发者资质（Owner 当前未注册，列入前置清单）。
- 决策稿 §1.8、§7、§10 中涉及 Telegram 的表述以本 ADR 为准。
